## Package Overview

**plot2** is a high-level R wrapper around `ggplot2` designed to
minimise typing while producing complex, publication-ready plots. The
central idea: one call to
[`plot2()`](https://msberends.github.io/plot2/reference/plot2.md)
replaces many separate `ggplot2` + `dplyr`/`tidyr` steps, including
automatic plot-type selection, in-line data transformations, axis
handling, and custom theming.

- CRAN/GitHub: <https://github.com/msberends/plot2>
- Docs site: <https://msberends.github.io/plot2>
- License: GPL-2
- Requires R ≥ 4.1.0, ggplot2 ≥ 4.0.0

## Coding Style

### Formatting

- **Indentation**: 2 spaces (set in `plot2.Rproj`; no tabs).
- **Line length**: keep readable; wrap long parameter lists with one
  argument per line.
- **Braces**: opening brace on the same line as the control structure or
  function header.

### Naming

| Kind | Convention | Example |
|----|----|----|
| Exported functions | `snake_case` | [`plot2()`](https://msberends.github.io/plot2/reference/plot2.md), [`get_colour()`](https://msberends.github.io/plot2/reference/colour.md), [`theme_minimal2()`](https://msberends.github.io/plot2/reference/theme_minimal2.md) |
| Internal helpers | `snake_case` (no prefix) | `like()`, `font_black()`, `group_sizes()` |
| S3 methods | `function.class` | `plot2.data.frame`, `format2.Date` |
| Package environment | `plot2_env` | `plot2_env$reg_cols` |
| Internal NSE columns | `_var_x`, `_var_y`, … | prefixed with `_` to avoid clashes |
| Options | `plot2.<name>` | `plot2.colour`, `plot2.font` |

### Documentation (roxygen2)

- Markdown is enabled (`Roxygen: list(markdown = TRUE)` in DESCRIPTION).
- Use `[function()]`, `[pkg::function()]`, and `[topic]` links freely.
- Parameter lists for multi-possibility arguments use a bullet list
  under `@param`.
- Group related functions with `@rdname`.
- Every exported function must have a `@examples` block.
- Internal helpers use `@keywords internal` (no `@export`).
- Never edit `man/` or `NAMESPACE` by hand – always regenerate with
  `devtools::document()`.
- Roxygen blocks must end with `@examples`.

``` r

#' Short Title
#'
#' @description Full description. The [plot2()] function …
#'
#' @param .data Data to plot.
#' @param x One of:
#' - A single variable, e.g. `x = column1`
#' - A function, e.g. `x = format(date, "%Y")`
#'
#' @return A [`ggplot`][ggplot2::ggplot()] object.
#' @export
#' @examples
#' iris |> plot2(Species)
```

### Error / Warning Handling

- Always use `call. = FALSE`:

  ``` r

  stop("message", call. = FALSE)
  warning("message", call. = FALSE)
  ```

- Use the package’s own wrappers for user-facing messages:

  ``` r

  plot2_message("informational text")   # coloured blue via crayon
  plot2_warning("warning text")         # coloured yellow
  ```

### NSE (Non-Standard Evaluation)

- Internal temporary columns are prefixed with `_` (e.g., `_var_x`,
  `_var_category`).
- All such names are declared in
  [`globalVariables()`](https://rdrr.io/r/utils/globalVariables.html)
  inside `R/utils.R` to suppress R CMD check notes. Add new NSE names
  there when needed.

### Custom Operators (defined in `R/utils.R`)

| Operator     | Purpose                                        |
|--------------|------------------------------------------------|
| `%like%`     | Case-insensitive regex match (`grepl` wrapper) |
| `%unlike%`   | Negated `%like%`                               |
| `%>%`        | Re-exported pipe from dplyr                    |
| `%+replace%` | ggplot2 theme replacement (imported)           |

## Testing

- Framework: **testthat edition 3** (`Config/testthat/edition: 3` in
  DESCRIPTION); `vdiffr` and `withr` in Suggests.
- Infrastructure (see \#156):
  - `helper-plot2.R`: accessors (`geoms()`, `layer_df()`,
    `label_text()`, `axis_breaks()`, `axis_labels()`, `scale_values()`,
    `theme_el()`, `facet_info()`, `col_hex()`, …),
    `plot2_diagnostics()`, and expectations (`expect_plot2()`,
    `expect_geoms()`, `expect_labels()`, `expect_axis_breaks()`,
    `expect_scale_values()`, `expect_facets()`,
    `expect_plot2_message()`, `expect_clean_state()`,
    `expect_plot2_snapshot()`). Every custom expectation reports exactly
    one result.
  - `helper-fixtures.R`: small deterministic fixtures `fx_*`; add shared
    data there, not inline.
  - `setup.R`: deterministic environment (UTC, C locale, plot2 options
    reset).
  - `test-helpers.R`: self-tests of the helpers; extend it whenever a
    helper is added or changed.
- Test files: per-topic files only; the smoke tests of the former
  `test_plot2.R` are in `test-legacy-*.R` (skipped on CRAN). Group
  prefixes: `test-plot2_exec-<topic>.R` (stages of `plot2_exec()`),
  `test-modules-<topic>.R` (methods and modules), `test-api-<topic>.R`
  (documented behaviour), `test-themes-<topic>.R` (cross-cutting
  themes), `test-shiny-<topic>.R` (Shiny server, driven with the
  `shiny_*()` helpers), `test-validate-<function>.R` (one file per
  `validate.R` function) and `test-regression-<topic>.R` (fixed issues).
  Test files and descriptions carry no case IDs; in
  `test-regression-*.R` every `test_that()` description starts with the
  GitHub issue number (e.g. `"#13 ..."`).
- Tests for open GitHub issues describe the desired behaviour and start
  with `skip_open_issue("#123")`. When fixing the issue, remove that
  line and the test must pass. Known soft deprecations caused by plot2
  are silenced per test with `local_known_deprecation("#123")`, never
  globally.
- Test content, not only class: prefer `expect_geoms()`,
  `expect_labels()` etc. over `expect_s3_class(p, "gg")`.
  `expect_plot2()` renders the plot and fails on R warnings.
- CRAN core (#50): on CRAN only a small core runs, which must finish
  within 1 minute (about 20 seconds locally). Every test file outside
  the core starts with a file-level `skip_on_cran()` directly below the
  header, so the files without it form the core. New test files get this
  skip; add a file to the core only after timing the CRAN run with
  `NOT_CRAN=false`. Such a local run deletes the vdiffr snapshots as
  unused, so restore `tests/testthat/_snaps` from git afterwards. Guard
  every use of a suggested package with `skip_if_not_installed()`.
- The full suite takes several minutes: run it detached and read the
  log.

### Running Tests

## Key Patterns

### S3 Dispatch

[`plot2()`](https://msberends.github.io/plot2/reference/plot2.md) uses
S3 dispatch to handle different input classes. The generic is in
`R/plot2.R`; methods are in `R/plot2-methods.R`:

    plot2.default      – vectors, and objects that broom::augment() or ggplot2::fortify() turn into a data frame (e.g. lm, table)
    plot2.data.frame   – the primary method (most logic lives here)
    plot2.matrix       – correlation matrices → heatmap
    plot2.sf           – simple features / geographic data
    plot2.freq         – cleaner::freq() tables
    plot2.formula      – formula interface

### Colour S3 Class

`get_colour.R` defines a `colour` vctrs-compatible S3 class with methods
for `as.character`, `print`, `c`, `rep`, `rev`, `unique`, and
`vec_cast`. Users register project colours with
[`register_colour()`](https://msberends.github.io/plot2/reference/colour.md)
/
[`unregister_colour()`](https://msberends.github.io/plot2/reference/colour.md);
they are stored in `plot2_env$reg_cols`.

### Parameter Grouping Convention

[`plot2()`](https://msberends.github.io/plot2/reference/plot2.md)
parameter names follow a consistent dot-namespacing pattern:

| Prefix | Controls |
|----|----|
| `x.` | x-axis settings (`x.title`, `x.sort`, `x.max_items`, …) |
| `y.` | y-axis settings (`y.title`, `y.transform`, `y.limits`, …) |
| `facet.` | facet settings (`facet.nrow`, `facet.position`, …) |
| `datalabels.` | data-label settings (`datalabels.size`, `datalabels.colour`, …) |
| `smooth.` | smoothing settings |
| `y_secondary.`, `title.`, `subtitle.`, `legend.` | settings of these elements |

Naming rule (see API Decisions below): `<argument>.<setting>` only where
the part before the dot is itself a
[`plot2()`](https://msberends.github.io/plot2/reference/plot2.md)
argument, with the setting in snake case (`x.label_angle`,
`facet.repeat_labels_x`); everything else is plain snake case
(`colour_fill`, `sankey_node_width`, `jitter_seed`). Exceptions: base-R
names `na.rm`, `na.replace`, `decimal.mark`, `big.mark`; and
`legend.value` in the `add_*()` functions. Automatic defaults are `NULL`
in the usage (#106); explicit values mean what they say. Options are
prefixed `plot2.` (e.g. `plot2.decimal.mark`).

Single argument definition (#47): the arguments are defined once, in the
generic
[`plot2()`](https://msberends.github.io/plot2/reference/plot2.md) in
`R/plot2.R`. The methods and `plot2_exec()` get their formals in
`R/zzz.R` (`plot2_method_formals()`), and forward everything with
`eval(plot2_exec_call())`. A new argument is added only to the generic
(plus its `@param`), and used in `plot2_exec()`.

### validate\_\*() Functions

All argument validation happens in dedicated `validate_*()` functions in
`R/validate.R` (e.g., `validate_type()`, `validate_legend.position()`).
Keep validation out of the main function body.

## Adding New Plot Types

1.  Add type aliases/detection in `R/validate.R` inside
    `validate_type()`.
2.  Implement the geom layer in `R/plot2.R` (or a dedicated file like
    `R/back2back_plot.R` for complex types).
3.  Register any new NSE column names in
    [`globalVariables()`](https://rdrr.io/r/utils/globalVariables.html)
    in `R/utils.R`.
4.  Add `@importFrom` tags and re-run `devtools::document()`.
5.  Write tests in a per-topic file in `tests/testthat/` using the
    helpers in `helper-plot2.R`.
6.  Document the new type in the `@param type` block in `R/plot2.R`,
    update `vignettes/supported_types.Rmd` (section and table), and add
    it to `data-raw/plot_types_overview.R` (then re-run that script).

  argument names; show the code of every displayed plot.

  `test-api-vignette-supported-types.R` and

## API Decisions

The maintainer’s decisions on argument names and defaults, made before
the first CRAN release (from proposal \#159). The package is not on
CRAN, is beta and has no known users, so breaking changes are made
directly, without aliases or deprecation, until the first CRAN release.
API changes need the maintainer’s consent per item, not per group.

### Design principle

`plot2` exists to streamline `ggplot2`, whose API requires knowledge of
hundreds of arguments across tens of functions. User-facing concepts
(`type`, `category`) come first; `ggplot2` concepts (geoms, aesthetics)
stay in the background. Follow `ggplot2`’s names where that is not
unclear or complex, and depart from them where it helps users.

### Naming rule

`<argument>.<setting>` with the setting in snake case, only where the
part before the dot is itself a
[`plot2()`](https://msberends.github.io/plot2/reference/plot2.md)
argument (`x`, `y`, `category`, `facet`, `y_secondary`, `title`,
`subtitle`, `datalabels`, `smooth`, `legend`); everything else is plain
snake case. Exceptions: base-R names `na.rm`, `na.replace`,
`decimal.mark`, `big.mark`; and `legend.value` in
[`add_line()`](https://msberends.github.io/plot2/reference/add_type.md),
[`add_point()`](https://msberends.github.io/plot2/reference/add_type.md),
[`add_col()`](https://msberends.github.io/plot2/reference/add_type.md)
and
[`add_smooth()`](https://msberends.github.io/plot2/reference/add_type.md).

### Decided items

| Item | Decision |
|----|----|
| Automatic defaults | `NULL` in the usage, documented as “determined automatically”; explicit values mean what they say (#106). |
| `colour_opacity`, `get_colour(opacity = )` | Renamed to `colour_transparency` and `transparency`, same meaning (0 = solid, 1 = transparent). |
| `x.lbl_angle`, `x.lbl_align`, `x.lbl_italic` | Renamed to `x.label_angle`, `x.label_align`, `x.label_italic`. |
| `facet.repeat_lbls_x`, `facet.repeat_lbls_y` | Renamed to `facet.repeat_labels_x`, `facet.repeat_labels_y`. |
| `sankey.node_width`, `sankey.node_whitespace`, `sankey.alpha`, `sankey.remove_axes` | Renamed to `sankey_node_width`, `sankey_node_whitespace`, `sankey_alpha`, `sankey_remove_axes` (there is no `sankey` argument). |
| `facet.fill` | Renamed to `facet.colour_fill`. |
| Options `dec_mark`, `big_mark` | Renamed to `plot2.decimal.mark`, `plot2.big.mark`; the functions [`dec_mark()`](https://msberends.github.io/plot2/reference/dec_mark.md) and [`big_mark()`](https://msberends.github.io/plot2/reference/dec_mark.md) keep their names and read these options. |
| `x.mic`, `x.lbl_taxonomy` | Removed from [`plot2()`](https://msberends.github.io/plot2/reference/plot2.md); replaced by [`AMR::scale_x_mic()`](https://amr-for-r.org/reference/plot.html) and `AMR::labels_taxonomy()` of the `AMR` package, which is not a dependency. |
| `legend` | New argument: `NULL` (automatic), `TRUE` forces, `FALSE` hides. The legend is only the plot element explaining `category`; the `legend.*` settings keep their names. |
| `legend.position` | Keeps `"none"` as an alternative way to hide; `NULL` means automatic. |
| `legend.title`, `category.title` | Both kept as one setting; giving both stops with an error. |
| `stacked`, `stacked_fill` | Both kept; `stacked = "fill"` equals `stacked_fill = TRUE`; on conflict `stacked_fill = TRUE` wins. |
| Kept as they are | `jitter_seed`, `violin_scale`, `category.type`, the prefix `y_secondary`. |

Renamed and removed arguments give a clear error (`plot2_old_args` in
`R/zzz.R`).
